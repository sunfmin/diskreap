diskreap plan [--rule ID] [--path P] [--all] — what clean would delete and hold, changing nothing.

WHEN   Before clean, to see what it would do.
WHO    Anyone.
READS  The Rule list from the gist, every Match of each Rule and everything in
       it, lsof, ps, git and the apps installed. WRITES nothing.

  --rule ID   only this Rule
  --path P    only P, and only when it is a Match of a Rule: its glob reaches
              it and its marker is beside it. Nothing is walked but P, so
              it is quick. P must be real: no symlink, `.` or `..` in it.
  --all       every Match, not only the ten largest of each Rule

ANSWERS
  gist              the gist's id
  rules             for each Rule id:
    glob              its glob
    matched           how many Matches it has
    deletable, deletable_bytes   those clean would delete, and their size
    held, held_bytes  those it would keep, and their size
    holds             how many are held for each reason: floor, recent,
                      in_use, running, installed, not_yours, unreadable,
                      git_tracked, holds_repo, other_volume
    largest           the ten largest Matches (matches, with --all): path,
                      bytes, verdict (delete or hold), holds (why, in words),
                      bytes_at_least (true when a held Match was not read to
                      the end: reading stops at the first thing that holds it)
    seconds           how long its walk took; Rules that search any depth
                      from the same place share one walk, and its time
    error             instead of the above, when its glob no longer compiles
  matched, deletable, deletable_bytes   the totals
  note              what the byte counts mean
  path              with --path, the path judged
  why               with --path, when no Rule matches it: why that can be
  seconds           how long the run took

EVENTS (stderr, one JSON object a line, as they happen)
  {"event":"start","rule":...}, then {"event":"match","rule","path","bytes",
  "verdict","holds"?} for each Match, then {"event":"rule",...} when a Rule is done.

TRIPS YOU UP
  A Match held as recent may go on a later run: holds say when.
