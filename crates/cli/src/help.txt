diskreap — frees disk space on this Mac by Rules kept in a private gist, and
deletes only what is safe.

A Rule names one kind of thing that may be deleted: a file glob, the
conditions under which a Match may go, and why it is safe. Every Rule exists
because a person agreed to it. The Rule list lives in one private gist of
yours (file diskreap-rules.json) and is read again on every run; diskreap
keeps nothing on this machine.

WHAT IT NEEDS
  macOS, and gh logged in with the gist scope (`gh auth login`).
  lsof, ps, git, plutil, mdfind and df, which come with macOS and Xcode's tools.

RUN FIRST
  diskreap doctor     what is missing, each with its fix
  diskreap init       makes the gist when there is none

  The gist's id is remembered in ~/.config/diskreap/gist so a run need not
  list every gist; it is only a shortcut, looked for again when it is gone.

WHAT A RUN DOES
  Each Rule's glob is walked. A Match goes only when every check passes:
    - the floor: never `/`, `~`, `~/Library` or anything directly in either;
      never outside ~ and your own /var/folders entry; never a git repository
      or anything git tracks; never through a symlink or onto another volume;
      never another user's file. No Rule can change the floor.
    - nothing anywhere in it was changed or used within the Rule's min_age
      (default 1d): a file's last use is the newest of its writes and its
      access time, a read counting as a day later than the access time says
      (macOS moves it at most daily); where no access time can be read,
      the writes alone;
    - no process holds a file in it open or works in it (lsof);
    - none of the Rule's unless_running programs runs, and none of its
      unless_installed apps is installed;
    - with a marker, that file sits beside it (`Cargo.toml` beside `target`).
  Anything that fails a check is held, and the answer says why.

COMMANDS
  For anyone, changing nothing:
    diskreap doctor                 checks what diskreap needs
    diskreap plan [--rule ID] [--path P] [--all]
                                    what clean would delete and hold
    diskreap scan                   large directories no Rule covers
    diskreap rule list              the Rule list
    diskreap rule check RULE        what a Rule would match, not adding it
  Changing the gist (only after a person agreed):
    diskreap init                   makes the gist
    diskreap rule add RULE          adds a Rule
    diskreap rule set ID --min-age AGE | --why TEXT
    diskreap rule rm ID
  Deleting:
    diskreap clean [--rule ID] [--path P] [--all]
                                    deletes each Match nothing holds, at once

  `diskreap <command> --help` says what a command answers, every key.

THE WAY TO ADD A RULE
  1. diskreap scan, or look yourself, to find what takes space.
  2. Write the Rule; diskreap rule check '<rule>' shows what it would match.
  3. Show the person the Rule and that answer; add it only when they agree:
     diskreap rule add '<rule>'.

A RULE
  {"id": "cargo-target", "glob": "~/**/target", "marker": "Cargo.toml",
   "min_age": "1d", "why": "cargo builds it again"}
  id                short name: lowercase letters, digits, `-`
  glob              starts at ~/, $TMPDIR/ or $VARFOLDER/ (your /var/folders
                    entry, where $TMPDIR is its T); `*` and `?` in a name,
                    `**` for any depth of directories, which skips ~/Library,
                    ~/.Trash and .git unless the glob starts inside them
  marker            a file that must sit beside a Match; needed with `**`
  min_age           30m, 12h, 1d, 2w; default 1d
  unless_running    programs: while one runs, nothing goes
  unless_installed  app names or bundle ids: while one is installed, nothing goes
  why               why what it matches is safe to delete

OUTPUT
  Every command prints one JSON object on stdout when it ends; a failure is
  {"error": "..."} with exit 1, and says the line that fixes it.
  The exception: while plan, clean, rule check, rule add and scan walk, each
  Match, deletion and finding is printed as it happens, one JSON object a line
  on stderr ("event": "start", "match", "deleted", "failed", "rule", "large",
  "tmpdir", "orphan"), so a long run can be watched, and acted on, as it goes.
  Walks run on several threads; Rules that search any depth from the same
  place share one walk, so the events of several Rules come interleaved.
  Byte counts are allocated blocks: an APFS clone counts in each copy, so
  they can add up to more than clean frees. clean measures what it freed.
